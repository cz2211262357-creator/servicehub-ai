# Java 客服执行与取消

客服业务和受控 Agent 均运行于 Java。模型适配使用 Spring AI 的 OpenAI HTTP 传输与官方 OpenAI Java SDK，对接百炼兼容端点；没有引入 LangChain 或 LangGraph。独立问数 Agent 属于后续项目。

## 一轮执行

消息接收事务保存唯一 client_message_id、原 accepted_generation_epoch、run/job/Outbox；Worker 只能领取数据库中仍合法的任务。普通追问走确定性规则，明确新话题/恢复/修改采用相应路由。仅含糊指代调用一次结构化分类，候选 topic 由当前授权会话提供，模型不得创建任意恢复目标。

分类领取标记在 HTTP 请求前持久化。自动重试和租约恢复保留标记及已保存决策；只有标记没有决策时转为等待用户选择。保存的决策不是授权结论，使用时仍重新检查候选、会话、授权、epoch 和租约。等待用户输入会释放运行资源，不通过后台续约无限等待。

解析成功后，只组装本话题中可用于上下文的用户消息和完成回答，最多20条、16000字符；已取消、部分流、未解析消息和失效知识引用的旧回答不进入提示词。先检索知识，再执行模型与工具回环。工具只有 search_policy、lookup_order、prepare_after_sale。订单来自服务端已验证话题对象；客户端和模型都不能提供 tenant/actor 覆盖身份。

prepare_after_sale 仅创建或复用带 topic/run/epoch/budget_revision 的草稿。正式工单仍由客户明确确认接口提交；模型不能调用退款、支付、发货或正式工单确认。取消聊天不会回滚已被客户合法确认的业务。

## 预算与资源

首次领取固定整轮 deadline，前台默认120秒，包含分类、检索、排队、模型等待、工具和供应商请求。每次模型 HTTP timeout 取45秒与数据库剩余时间较小值，取得模型名额后再次计算。不会在每次模型调用或 Worker 重领时刷新120秒。

前台 Embedding、分类和对话共用持久六次请求预留；工具最多四次。预留先于网络，失败和重启不退回计数。每个输出最多1600 tokens，序列化消息与工具定义合计最多24000字符，超额明确失败，不伪造完成。文档导入属于独立后台预算。

执行和模型各有全局四个名额，后台最多占三个。单次供应商请求领取模型名额，完成即释放；整轮 Agent 不持有模型名额后再嵌套申请。Redis owner/续约用于协调，数据库租约令牌、状态和 deadline 决定最终写入是否合法。

## 流、工具与最终提交

SSE 工具参数可能拆成多个分片：先有界组装，验证结束原因、完整 JSON 和白名单参数后才执行。半个工具调用、截断响应、永久错误不会被当成成功。每次工具、模型、分片和提交均检查取消。请求取消显式调用对应 HTTP Call.cancel，不取消其他任务的 HTTP；外部供应商已消耗的计算无法据此保证退回。

模型 HTTP 和等待期间不持有业务行锁。草稿工具采用授权用户→会话→订单→run/job的短事务。最终回答采用授权用户→会话→排序后的引用文档→run/job，重新核验权限、当前来源、topic/epoch/run、budget revision、owner/token、租约及 deadline；回答、任务完成、事件和审计在同一事务提交，任何 fence 丢失全部回滚。

一次执行最多使用30条不同检索来源；提交前检查全部模型可见来源，公开引用最多6条。工具轨迹公开名称和执行摘要，不保存模型内部思考链。

## 供应商统计和故障

官方 Spring AI 上层流式模型会在 usage 缺失时合成零值，因此适配直接读取官方 SDK 原始分片并保留缺失：缺失 usage 为 null，真实零值保留0，局部缺失字段仍为 null。ai_runs.usage 是本轮对话回环实际返回用量的汇总；它不包含未返回的用量，也不是账号总账，不用估算值冒充真实消费。

官方 SDK 自动重试关闭。暂时性故障是否重试由持久任务状态控制，自动总尝试最多3次，前两次退避5/30秒；明确取消、权限失效和永久性错误不自动重试。同一个逻辑任务在网络故障下仍可能重复消耗供应商请求；系统保证业务提交幂等，不声称模型物理执行恰好一次。

当前集成测试使用可控 HTTP 供应商与真实 MySQL/Redis/RabbitMQ，验证协议、资源和竞态；真实百炼验证与整体多进程故障验收单独进行，不能以替身测试替代。
