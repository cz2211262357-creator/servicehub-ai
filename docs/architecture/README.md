# 架构与并发设计

ServiceHub 是模块化单体 API 与独立 Worker。React 通过同源 HTTP、只读 WebSocket 访问 API；MySQL 是业务权威源。Redis 负责登录会话、Lua 限流、模型并发槽、跨进程通知、Streams 和 HNSW。业务一致性不依赖某个 API 进程的内存。

~~~mermaid
flowchart LR
    UI[React / TypeScript] --> WEB[Nginx]
    WEB --> API[FastAPI 多进程]
    API --> DB[(MySQL)]
    API --> R[(Redis)]
    W[Worker + Outbox] --> DB
    W --> R
    W --> M[百炼 qwen-plus]
    W --> E[text-embedding-v4]
    R --> API
~~~

## 身份与业务边界

登录使用随机 256 位标识、Redis 摘要索引、Argon2id 密码、8 小时会话、HttpOnly Cookie。写请求检查 CSRF 与来源，WebSocket 检查 Origin，并在订阅期间重验身份。成员权限变化增加 session_version。

租户从服务端 Principal 推导。所有业务表具有 tenant_id；复合外键阻止跨租户关联。客户只读本人订单、会话与售后；客服处理本租户会话；管理员管理成员、知识和任务。跨租户资源返回不可见。金额使用 Decimal，数据库时间使用 UTC DATETIME(6)。

## 业务并发保证

| 场景 | 机制 | 验证 |
|---|---|---|
| 重发消息 | 租户＋会话＋client_message_id 唯一；相同 ID 不同正文拒绝 409 | 双 API 20 请求只有一条消息与一个 AI 任务 |
| 多客服抢单 | 会话版本与状态条件更新 | 双 API、20 名不同客服只有一人成功 |
| 售后重复确认 | 客户/草稿短行锁、请求摘要、唯一幂等键和唯一草稿约束 | 双 API 20 次确认生成一张工单 |
| 人工接管与 AI 迟到 | generation_epoch、状态和租约三重提交校验 | 延迟模型在接管/租约失效后不能保存正式回复 |
| Worker 崩溃 | MySQL 任务租约、execution_version、Streams 待确认重投 | 实际终止进程，过期后另一个进程恢复，旧执行提交被拒 |
| Redis 通知丢失 | MySQL 单调事件序号，客户端重连游标补放 | 两个 API 进程接收相同事件；慢消费者断开后可补放 |

消息、会话事件、AI 运行、后台任务与 Outbox 在同一 MySQL 事务创建。网络调用不持有业务行锁。投递至少一次，消费者幂等与提交围栏消除重复业务结果；不能宣称消息传递本身“恰好一次”。

Worker 使用 XREADGROUP/XAUTOCLAIM 和有界并发，Outbox 投递与回收独立于任务执行循环，慢任务不会堵塞空闲槽位。单项执行失去租约时只取消该项任务。数据库租约按数据库时间续期。API、Worker 都能横向启动多个实例，但连接池、模型全局槽及供应商额度仍需按实际部署容量配置。默认模型全局并发 4，单 Worker 并发 4。自动重试为首次执行后最多三次，最终失败由管理员手动重试并审计。重试、最终失败和重新排队同时更新 AI 运行或文档版本状态；会话快照携带当前任务状态，刷新页面后仍能分辨排队、执行、重试和最终失败。

## RAG 与受控 Agent

管理员上传 TXT/Markdown/文本 PDF，最大 10 MiB。源文件保存在鉴权私有卷；版本、分块、页码、SHA256 和有效版本在 MySQL。解析/分块移出事件循环，Embedding 按批发送。新版本索引成功后在短事务切换有效版本。

在线检索在候选排名前筛选本租户启用、未删除、就绪的有效版本，再做 MySQL ngram 全文候选与 Redis HNSW 余弦候选，RRF 合并后再次通过 MySQL 授权复核。全文无结果时最多取 16 个词元做有限字面回退，该路径需按目标规模测量。Redis 索引键按模型和维度隔离，并带版本 TAG；旧索引通过 FT.ALTER 和幂等元数据补齐升级，无需重新调用模型。提交回复前再次检查文档有效性；停用文档不会继续作为新回复引用。历史引用链接固定到生成回答时的文档版本；客户访问旧文件还需在其本人会话中存在对应引用，避免读到其他版本。已经发送的引用快照保留为历史记录。

对话调用百炼 qwen-plus，Embedding 为 text-embedding-v4/1024。实际支持 SSE 片段拼接、完整工具参数解析、超时和 429。仅暴露 search_policy、lookup_order、prepare_after_sale。工具按当前客户身份二次授权；不提供 SQL、支付、直接退款工具。售后草稿必须由客户在页面明确确认，才能生成正式工单。检索内容标记为不可信资料，缺乏依据时提示无法核实并提供转人工入口。

模型调用限制输入、输出、工具步数和总耗时。所有供应商 usage 仅记录实际返回值，未返回则为空。费用未接入供应商账单，界面不会推算成真实费用。

## 观测与已知边界

请求日志包含请求标识、路由模板、状态和耗时；工具轨迹只记录参数字段名、结果和错误代码。没有请求体、密码、模型 Key 或思考过程日志。运营图表来自真实租户 SQL 聚合，Prometheus 入口要求管理员身份。

当前范围是本地可运行的完整工程。业务数据是可替换的虚构商家种子；未连接生产电商、支付和物流系统。文本 PDF 不含 OCR，没有独立 reranker、自动退款、跨地区容灾或 Kubernetes。对话模型/Embedding 服务是实际在线调用；生产上线仍需配置域名 HTTPS、独立凭证、备份保留策略和目标环境容量测量。
