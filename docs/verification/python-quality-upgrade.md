# Python 平台升级与评估汇总

本页只公开项目源码、合成题库与汇总指标。逐例运行轨迹、原始评估报告和本机页面截图留在本地，不随此分支上传。

## 实现范围

- React / TypeScript + FastAPI + MySQL + Redis，真实百炼 qwen-plus 与 text-embedding-v4。
- Redis BM25STD + HNSW + RRF，中文查询归一化、租户与有效版本过滤、最终SQL授权。
- 后端按可信品类、签收时间、商品状态和保修事实强制校验售后资格；准备与客户确认均复核。未知资料须澄清或人工，不由模型补写事实。
- 普通追问保留已成功草稿；明确换单或撤回使旧草稿失效；取消费用等疑问不当作命令。口头同意不代替客户按钮确认。
- 模型/工具/检索持久Trace，参数摘要脱敏；管理端展示AI终态失败率、人工接管率、P95、已知Token和价格配置后的估算成本。
- 30份版本化合成商家政策、150条离线案例（5类各30），另有独立开发集。测试程序运行实际HTTP、任务、Agent、工具和数据库，不只调用模拟工具。

## 检索实测

相同30份政策、分块、qrels、30条政策问题和真实1024维向量，新旧FLOAT32向量字节一致；两路候选各30，RRF k=60。

| 检索方案 | Recall@5 | MRR@10 |
|---|---:|---:|
| 原MySQL ngram + HNSW + RRF | 0.8000 | 0.8444 |
| 新Redis BM25STD + HNSW + RRF | **0.9000** | 0.8678 |
| BM25STD单路 | 0.8000 | 0.7281 |
| HNSW单路 | 0.8556 | **0.9167** |

配对bootstrap2000次：Recall差值+0.10，95%CI [0.0167,0.1833]；MRR差值+0.0233，区间[-0.05,0.10]跨0，不能断言稳定改善。向量单路本次MRR更高。中文词项归一化同时变化，比较的是完整检索管线。计时预热查询Embedding，排除索引和外部Embedding延迟。

真实调用qwen-plus；参考答案只用于执行后断言和隔离裁判，不注入在线Agent。题库没有随成绩改写。

| 类别 | 业务硬断言通过 | 同时满足严格回答质量 |
|---|---:|---:|
| 售后政策问答 | 29/30 | 29/30 |
| 本人订单查询 | 28/30 | 26/30 |
| 售后草稿执行 | 25/30 | 24/30 |

严格质量要求忠实度、相关性及必要引用质量各达到3/4，裁判150/150有效；不能覆盖程序安全失败。可观测权限安全硬门禁和工具白名单检查150/150通过，不代表覆盖所有潜在攻击。

首轮为126/150硬通过、115/150严格通过；修复包括流式null工具字段、输出截断、当前授权版本、澄清与政策引用边界、疑问误撤回以及旧向量回填。前后都保留本地完整结果，小幅变化不构成独立泛化或因果保证。

仍有22条业务失败，其中13条涉及引用缺失/无效导致的运行失败，其余9条以工具遗漏和多轮参数更新问题为主。另10条硬通过但语义质量不足。多轮与异常是主要短板；服务端没有因此越权提交或自动退款。

175轮交互P50=6.578秒、P95=19.406秒；不含裁判，不是并发容量。Agent已知702561 Token，裁判447553 Token，分开统计。Embedding接口当前不暴露用量；没有配置单价与价格版本，货币成本未知，不等于免费。

## 边界与取舍

- 150条已用于工程回归，不是独立留出集；同模型裁判可能共同偏差，qwen-plus别名内部修订未锁定。
- 引用与取消采用保守规则，复杂自然语言可能仍需澄清；引用ID存在不等于语义一定正确。
- 回退先重建并验证旧向量，再改mysql_legacy；维护期间暂停知识版本切换，不采用每次新文档都双写两引擎的耦合方案。
- 当前每次检索仍验证语料完整性，大规模批处理/后台校验优化尚待实施；未测百万级语料或生产最大吞吐。
- 商家与订单均合成，不包含真实ERP、支付退款、物流下单、扫描OCR或长期生产验证。Java主线保持独立。
