# InsightPilot 智能问数与经营分析 Agent 设计

日期：2026-10-22
状态：用户已批准设计并进入分阶段实施计划；尚未开始代码实现。作为 ServiceHub Java 迁移之后的独立项目实施。

## 定位

面向电商经营与售后分析，用户通过自然语言提出指标问题，Agent 确认口径、制定查询步骤、调用受控数据工具、校验结果并生成带证据的表格、图表和报告。项目突出状态化编排、工具调用、人工介入、只读数据权限、恢复与评测。

业务与客服即时问答区分：ServiceHub 负责办理客户服务，InsightPilot 负责跨订单、商品、渠道、售后等主题的数据分析。项目可独立启动与验证，无需先运行 ServiceHub。初始数据为明确标注的虚构经营数据，模型与工具执行使用真实链路。

## 技术与目录

- Python、FastAPI、uv：独立服务、认证和任务 API。
- LangGraph：规划、查询、校验、报告节点以及暂停、恢复和持久化状态。
- PostgreSQL：经营数据、分析任务、结果与审计；LangGraph 使用官方 PostgreSQL checkpointer，权限分别配置。
- SQLGlot：SQL 结构解析与访问策略校验。
- MCP Python SDK：将指标目录、查询提交及只读执行封装为真实工具服务，使用受保护的 Streamable HTTP 接口。
- Pandas、Plotly、React / TypeScript：数据整理、受约束的图表配置和问数工作台；不执行模型生成的任意 Python 或 JavaScript。
- Redis：限流、全局模型并发槽和短期通知；PostgreSQL 是任务与状态的权威源。
- 对话模型沿用百炼在线 API，默认 qwen-plus。版本与工具协议依赖在实施计划中锁定稳定版本。

项目代码放在 projects/insightpilot-agent/，具有独立 pyproject、依赖锁、前端、Compose、测试与 README；全部工具缓存、环境及数据仍位于用户指定的 D 盘项目目录。可将这一目录单独打包交付。

本地端口范围为 Web 8090、API 8010、MCP 8011、PostgreSQL 5433、Redis 6382，全部绑定 127.0.0.1，启动前检查占用。

## 典型用户流程

问题示例：“上个月华东地区的售后率为什么比前一个月高？主要是哪些品类？”

1. 读取已授权的数据集与指标目录，检查“售后率”、地区、时间范围和订单状态的定义。
2. 关键口径缺失时暂停，请用户确认；展示简短计划与假设，不展示模型内部思考链。
3. 规划总体比较、品类分解和原因证据查询，生成受约束 SQL。
4. 工具服务检查身份、表/列权限、SQL 结构与查询预算，执行只读查询。
5. 对汇总与分组结果做确定性核对，必要时在限定次数内修正查询。
6. 生成图表和分析报告，区分数据支持的现象与分析推断，附指标定义、时间范围、查询证据和数据版本。
7. 用户追问可复用已确认口径；进程中断后恢复未完成任务。

UI 包含问数工作台、分析记录与指标目录。工作台展示当前阶段、待确认事项、查询摘要、结果表、图表和报告引用。

## Agent 状态图与工具

状态图：理解问题 → 读取指标与数据目录 → 口径确认（必要时暂停）→ 规划 → SQL 生成 → 策略校验 → 只读执行 → 结果校验 → 报告 → 完成。

策略拒绝不会降级为直接执行。SQL 语法或字段错误可进入有界修正；权限错误直接终止。执行失败、超预算、等待确认和取消都以明确状态保存。

MCP 数据服务提供以下最小能力：

- list_datasets：返回当前身份有权使用的数据集与字段摘要。
- get_metric_definition：读取受管理的业务指标口径。
- validate_query：解析并保存 SQL、参数、授权范围与规范化摘要，返回 query_id。
- execute_query：按 query_id 加载已验证查询并再次校验身份与策略，返回受限结果与证据编号。

连接地址、账号、租户身份和查询权限不由模型参数决定。MCP 调用使用应用签发的短期身份上下文；模型仅看到工具参数和受限结果。

## 数据与权限

初始覆盖订单、订单明细、商品、渠道、地区和售后。定义支付销售额、净额、订单量、售后申请率、退款金额及平均处理时长，明确状态、日期和分母口径。

业务数据按两个租户构造，用于验证跨租户隔离；提供按固定种子生成的可重复数据和金标准 SQL。可选导入 ServiceHub 的显式导出文件，不直接访问它的运行库，也不要求共享数据库账户。

业务查询账号对外仅能查询白名单分析视图，不能写业务表或访问系统敏感信息。security_invoker要求调用角色具有底表SELECT，因此将底表置于business_private，授予必要SELECT但不给该schema的USAGE，仅开放analysis视图schema；这一实际授权边界已纳入用户2026-10-25审阅通过的实施计划，并以真实角色直接访问底表失败的测试验证。它不是表所有者，且无超级用户或 BYPASSRLS 权限；视图使用 security_invoker，底层表强制行级权限。每次查询由网关在事务内注入可信租户上下文，事务结束后自动清理，避免连接池串租户。状态存储与 checkpoint 使用单独账户和 schema，模型无法调用这些连接。

只允许单条只读 SELECT，CTE 也需递归检查。拒绝写操作、SELECT INTO、锁定读取、COPY、外部连接、危险函数、多语句及非白名单表列。函数按白名单开放 COUNT、SUM、AVG、MIN、MAX、DATE_TRUNC、COALESCE、NULLIF、ROUND 等必要能力；拒绝 set_config、pg_sleep、文件/网络及用户自定义函数。数据库只读事务与 statement_timeout 再次约束执行。

默认限制：每次查询最多 1000 行、结果最多 1 MiB、数据库执行 3 秒；每个分析任务最多 8 次模型调用、4 次查询执行、2 次 SQL 修正；项目全局模型并发2、后台报告最多1个占用，保留1个交互名额；该限制不冒充供应商账号总配额。EXPLAIN 根节点 Total Cost 超过 10000 或估计输出行数超过 100000 时暂停请求确认，阈值可配置；确认不能解除只读、权限和硬超时限制。

## 状态、恢复与审计

每个分析任务使用独立run_id和graph thread_id，固定归属于conversation/topic，默认BACKGROUND_TOPIC。前台切换话题不取消报告，不以当前active_topic或前台epoch拒绝合法后台完成；显式取消或修改指定run才改变其任务状态/task_revision。重复请求用幂等键返回同一任务；同一任务仅允许一个有效执行者。数据库记录执行版本，持久化适配层在同一事务内锁定任务版本并写 checkpoint 或最终结果，旧执行不能覆盖恢复后的状态。

暂停确认时保存问题、口径、计划、规范化 SQL 摘要、授权范围与预算。确认绑定本run/task_revision、SQL hash、auth_version、预算与checkpoint摘要；内容/权限变化后原确认失效。单纯前台切话题不等于批准或取消，恢复必须显式指定原任务，不能把新消息当成HITL回复。取消后阻止继续查询和提交报告。

保存问题、公开计划摘要、工具名、脱敏参数、查询证据、状态变化、供应商实际 usage、错误码与耗时；不记录密钥、密码或内部思考链。默认使用本地审计与追踪，外部追踪平台连接属于显式可选配置。

每份报告中的关键数据可追溯到查询结果和指标口径。工具失败时展示失败，不由模型补造数值。

## 验收与评测

- 单独启动后，真实模型完成问数、口径确认、查询、图表和报告流程。
- 至少 20 条带金标准 SQL 的业务问题，覆盖金额、比例、趋势、分组、空结果与模糊口径；另覆盖跨租户、提示注入、危险 SQL、超时与超预算输入。
- 以查询执行成功率、结果与金标准一致性、口径确认正确性、证据覆盖、延迟和 Token usage 记录结果；实际跑完后报告数据，不预设虚构准确率。
- 进程退出后可恢复；重复提交、重复确认、旧执行迟到与取消都有回归验证。
- 权限用真实 PostgreSQL 角色及行级约束测试，超时和只读限制由数据库实际生效。
- 默认 CI 使用确定性模型替身验证工程逻辑；真实模型验收单独执行并标记调用开销。运行产品默认接真实供应商，不以内置固定回答替代在线能力。
- 交付源码、独立启动文档、状态图、工具协议、评测集、实测报告、关键源码讲解与可核实的简历项目条目。

## 第一版边界

支持经营数据只读分析与报告导出，不执行退款、不写回业务库、不发送外部消息，也不开放任意 Shell、Python 或网络访问工具。第一版以可管理的关系数据集为范围，未来的数据源连接扩展需另行定义权限和成本边界。

## 多轮对话补充要求

用户新增的对话打断与话题切换要求为必选范围，见 [共同补充设计](2026-10-22-conversation-interruption-design.md)。必须实现按任务scope取消、前台失效与后台继续分离、上下文白名单、安全恢复和对应竞态测试；状态/授权/fencing规则见[共同一致性规范](2026-10-22-execution-consistency-design.md)，独立阶段测试为[验收矩阵](../../verification/java-concurrency-acceptance.md)P01–P03。售后草稿与 Agent 执行确认分别管理；已提交业务结果不因打断被撤销。
